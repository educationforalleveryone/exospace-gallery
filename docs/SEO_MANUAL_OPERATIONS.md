## 1. Search engine properties

### 1.1 Google Search Console — PRIMARY (not yet configured)

Do this once the sitemap system (Iteration 4) is deployed.

1. Sign in at https://search.google.com/search-console with the operator account.
2. Add property → **Domain** → `exospace.gallery` (domain property covers all subdomains; the app is single-host today).
3. DNS verification: GSC shows a TXT record `google-site-verification=<token>`.
   - Where DNS lives: the DigitalOcean domain / registrar managing `exospace.gallery`.
   - Add the TXT record at the host `@` (or the GSC-provided hostname), TTL default.
   - Verification usually completes in minutes; click **Verify** in GSC.
4. **Record the verification token here** (internal doc — not public):
   - `google-site-verification` TXT: `________________________________`
   - Verified on: `____-__-__`
5. Submit sitemaps: `https://exospace.gallery/sitemap.xml` (the index; sub-sitemaps are discovered automatically).
6. Recommended GSC settings:
   - Settings → Crawl stats: leave defaults.
   - International targeting: leave unset (single-locale).
   - Users and permissions: add operator accounts as **full**; analytics viewer as **restricted** if needed.

### 1.2 Google Search Console — CUSTOM DOMAINS (per white-label gallery)

Each Studio-plan gallery on a verified custom domain should be validated by the *gallery owner* (their domain, their property). Exospace operators do NOT create properties for customer domains. Recommended guidance to give Studio customers (also surfaced in-app during Iteration 6 onboarding copy):

> "Add your domain to Google Search Console (Domain property), verify via your DNS provider, and submit `https://your-domain/sitemap.xml` — Exospace serves a sitemap containing your exhibition automatically."

### 1.3 Bing Webmaster Tools (not yet configured)

1. Sign in at https://www.bing.com/webmasters (Microsoft account; supports importing from GSC).
2. **Fast path:** use "Import from Google Search Console" — verification and sitemap carry over.
3. Otherwise: add site `https://exospace.gallery`, verify with the same DNS TXT approach (Bing issues its own `msverify` token) or via a CNAME.
   - `msverify` TXT/CNAME value: `________________________________`
   - Verified on: `____-__-__`
4. Submit `https://exospace.gallery/sitemap.xml`.

### 1.4 IndexNow (optional, recommended when content volume grows)

Bing + Yandex support IndexNow for instant URL submission. The app does not integrate it automatically (no fabricated pings); if adopted later, a per-entity ping on publish would be implemented behind a feature flag and documented here.

## 3. Analytics

### 3.1 Current in-app analytics
- `analytics_events` (view / focus / dwell / tour_start) via the throttled public `/gallery/{gallery}/track` endpoint.
- Daily rollups (`analytics_daily`) via `exospace:rollup-analytics` at 03:00.
- First-party only; no third-party page-level tracking is embedded, so no consent-banner changes are required by the SEO work.

### 3.2 Organic acquisition measurement (DEPLOYED in Iteration 7)
- First-party, session-scoped capture on every visitor's first page view: HTTP referrer, landing page, UTM params, and a classified channel (`organic` / `social` / `referral` / `campaign` / `direct`).
- At signup the session context is copied onto the user row (`users.acquisition_*`) — no third-party script, no consent banner changes required.
- **SEO console → Acquisition tab** (`/master-control/seo?tab=acquisition`): signups by channel, organic share, galleries created by organically-acquired users, top organic landing pages by resulting signups (30/90/365-day windows).
- Search-engine demand data (impressions/clicks/queries) is NOT measured by the app — use Google Search Console → Performance, or the official Search Console API (`searchconsole.googleapis.com`, OAuth service account) if automation is wanted later. Record any such setup here when it happens.

### 3.3 Optional third-party analytics
If a product decision adds Plausible/Fathom/GA4 later:
- Load it via the existing CSP-safe pattern (`@nonce`), respect `SESSION_SECURE_COOKIE`/cookie policy, and update `docs/SEO_AUDIT.md` performance notes (script budget ≤ 10 KB gzipped, no render-blocking).
- Record the property ID + consent policy here.

## 8. Operator notes & gotchas

- **Never** set `TRUSTED_PROXIES=*` in production — host-header spoofing breaks canonical URLs (audit SEC-1).
- The static `public/robots.txt` is replaced by a dynamic route in Iteration 4. If a rollback is ever needed, restore the archived copy from `docs/robots-legacy.txt`.
- Gallery pages on custom domains canonicalize to the gallery's custom domain root by design (`public_url`). The primary-domain `/gallery/{slug}` URL of a custom-domain gallery is intentionally non-canonical.
- `php artisan cache:clear` flushes SEO caches too — fine, but expect a brief thundering-herd on sitemap regeneration after large cache clears; prefer `seo:rebuild` which regenerates eagerly.

## 10. Structured data & internal linking (deployed in Iteration 3)

All schema is built by ONE service: `App\Services\Seo\SchemaBuilder`.
All related-content is produced by ONE service: `App\Services\Seo\InternalLinkingService` (capped at 6 links, cached 15 min).

| Page | Emitted graphs |
|---|---|
| `/` | Organization + WebSite (SearchAction deliberately omitted — no site search) |
| `/discover` (page 1) | CollectionPage + ItemList (first result page) |
| `/artists` (page 1) | CollectionPage + ItemList |
| `/venues`, `/venues/{slug}` | CollectionPage |
| `/gallery/{slug}` | dated → ExhibitionEvent; undated → CollectionPage; + ItemList of artworks (capped 60) |
| `/gallery/{slug}/artwork/{id}` | VisualArtwork |
| `/artist/{slug}` | Person + ItemList of works (capped 25) |
| All pages | BreadcrumbList (via `<x-breadcrumbs>`) |

### If social profiles ever get added
Set `seo.organization.same_as` in `config/seo.php` (array of URLs) — the Organization schema picks them up. Do not edit templates.

### Internal linking map
- Exhibition → 6 related exhibitions (shared artists weighted 10×, shared venue 2×, log-scaled views)
- Artist → 6 related artists (shared exhibitions)
- Artwork → 8 siblings + 6 works by the same artist in other exhibitions
- Hubs link to everything; footer links to all hubs

Related sections are **never** arbitrary: everything is publiclyViewable + non-empty + relevance-ordered. Cache key prefix `seo:related:*` (15 min TTL).

## 11. Sitemaps, robots & redirects (deployed in Iteration 4)

### Sitemap architecture (what to tell search engines)
| URL | Content |
|---|---|
| `/sitemap.xml` | Index of groups: static, galleries, artists, artworks, content |
| `/sitemap-{group}-{page}.xml` | Group sub-sitemaps (2,000 URLs/page) |
| `/sitemap-{page}.xml` | LEGACY → 301 to `/sitemap-galleries-{page}.xml` |
| `https://{custom-domain}/sitemap.xml` | Single-entry sitemap for that gallery |

- Submit ONLY `https://exospace.gallery/sitemap.xml` in Search Console — groups are discovered automatically.
- Caches: 30 min TTL + event invalidation (entity edits bump a version key; denormalized counter updates do NOT).
- Force refresh: `php artisan seo:rebuild`.
- Sitemap rules: only canonical indexable URLs; `seo_profiles.sitemap_include=false` forces exclusion; `true` overrides thin-content rules but NEVER the access gate.

### robots.txt
- Now dynamic (`/robots.txt` route; the static file was removed and archived to `docs/robots-legacy.txt`).
- **If you roll back this iteration**, restore `docs/robots-legacy.txt` → `public/robots.txt`.
- Primary host: rules from `config/seo.php → seo.robots`.
- Custom domains: allow-all + host-local sitemap reference.

### Managed redirects
- Table `seo_redirects`; middleware runs pre-routing on GET/HEAD.
- 301 = permanent (default), 302 = temporary, 308 = permanent preserving method.
- Source paths are normalized (lowercase, no leading slash, query-free).
- Redirect map cached 10 min — after bulk edits run `php artisan seo:rebuild`.
- ⚠️ Never create redirect loops — the middleware does not detect them; keep destinations final.

### Deployment checklist (Iteration 4)
1. `php artisan migrate` (seo_redirects table)
2. **Delete `public/robots.txt` if it reappears from an old branch** — it would shadow the dynamic route
3. Deploy (nginx template change included — Coolify rebuild picks it up)
4. Verify: `curl https://exospace.gallery/robots.txt` (dynamic rules), `curl https://exospace.gallery/sitemap.xml` (grouped index)
5. In Search Console: the old `/sitemap-1.xml` reference now 301s — resubmit `/sitemap.xml` once

## 12. SEO landing & editorial pages (deployed in Iteration 5)

### How to create a page (no developer required)
```bash
php artisan seo:make-page virtual-galleries --type=landing --title="Virtual Galleries"
# then edit blocks (tinker or admin UI in Iteration 6) and publish:
php artisan tinker
>>> App\Models\SeoPage::where('slug','virtual-galleries')->first()->update(['status' => 'published'])
```

| Type | URL | Notes |
|---|---|---|
| landing | `/{slug}` | Marketing/SEO surfaces (`/virtual-galleries`, `/3d-art-galleries`, …) |
| editorial | `/resources/{slug}` | Guides, tutorials, comparisons, use cases |

### Content model (blocks)
Typed JSON blocks validated against a closed allow-list — `hero`, `text`, `features`, `faq`, `cta`, plus LIVE content blocks `exhibitions`, `artists`, `venues` that render real platform content (structural anti-thin-page measure). No raw HTML passthrough (CSP/injection-safe). FAQ blocks automatically emit FAQPage schema; editorial pages emit Article schema.

### Lifecycle & indexing rules
- `draft` → public URL 404s; preview via `?preview={token}` (printed by seo:make-page); always noindex.
- `published` + `published_at` in the future → 404 until due (scheduling without cron).
- `noindex` flag → renders but never indexed; excluded from sitemap content group.
- Landing pages can NEVER shadow real product routes (fallback-route resolution against a cached slug allow-list).

### Keyword-strategy handoff (future)
When keyword research is done, the strategy lands as: new seo_pages (slugs + titles + block copy) + seo_profiles overrides on existing entities + (optionally) curated live-block headings. Zero template or route work.

### Deployment checklist (Iteration 5)
1. `php artisan migrate` (seo_pages table)
2. `php artisan config:clear` (fallback route)
3. No pages ship by default — the platform's public URL set is unchanged until an operator creates one.

## 13. SEO admin & operations tooling (deployed in Iteration 6)

### Super-admin console: `/master-control/seo`
| Tab | What it does |
|---|---|
| Health | Indexable counts (galleries/artists/artworks/pages) + actionable quality issues |
| Galleries | Per-gallery SEO overrides: title, description, canonical, robots, sitemap include, structured-data toggle |
| Artists | Per-artist SEO overrides (title/description/robots) |
| Redirects | Create/delete managed redirects (301/302/308) with hit counters |
| Content pages | List + publish/unpublish SEO pages; create with `seo:make-page` |
| (header) | "Rebuild SEO caches" button → `seo:rebuild` |

Access: super-admin + MFA (same middleware as the rest of master-control). Every mutation is written to `admin_audit_logs`.

### Curator-facing controls (gallery/artist edit forms)
- **Gallery edit**: "SEO title" + "SEO description" (optional; auto-generated when empty).
- **Artist edit**: same two fields.
- Advanced controls (robots/canonical/sitemap/structured-data) are intentionally **not** exposed to curators — super-admin only (legitimate-use split).

### Scheduled SEO audit
`exospace:seo-audit` runs daily at 04:30 (Coolify worker picks it up via `schedule:run`). Output → log; warnings → Slack via `OPERATIONAL_ALERT_WEBHOOK`. Reports platform data only — never fabricated search data.

### Daily operator workflow
1. Morning: check Slack for `SEO audit — issues found` messages.
2. Work the issues (mostly: galleries missing descriptions → nudge curators via the admin gallery list filter "Missing description").
3. After bulk fixes: `php artisan seo:rebuild`.
4. Weekly: compare GSC Pages report vs sitemap groups (see §5 routine).

## 14. Performance hardening (deployed in Iteration 7)

| Change | Effect |
|---|---|
| LCP image preloads (artwork + artist pages) | Main contentful paint begins immediately |
| nginx gzip: `application/xml`, `text/xml`, `application/rss+xml`, `text/plain` | Sitemaps/robots/feed ship compressed (~70% smaller) |
| Semantic layer discipline | Artwork list capped at 60 text links, no images inside; JSON-LD artwork list capped at 60 |
| Cache headers | sitemaps 30 min, robots 1 h, feed 30 min, OG images 1 h |
| Feed N+1 fixed | `withCount('images')` — one query for the whole feed |

3D experience untouched: no new render-blocking assets, no font changes, no body-scroll changes on the gallery page.
